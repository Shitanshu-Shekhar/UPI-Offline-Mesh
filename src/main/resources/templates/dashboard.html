Help center

How MeshPay works

A quick guide to the offline payment demo.

Getting started

What does offline payment mean here?

The browser encrypts a test instruction and saves it locally while disconnected. This is a simulator demonstration, not a payment network.

How are devices registered?

This version does not register personal devices. The backend provides virtual mesh nodes for demonstrating packet movement.

How do I send an offline payment?

Select a seeded demo account and recipient, enter a small demo amount, review it, provide a demo PIN, and queue the encrypted instruction. If the browser is online, the app attempts to sync it to the simulator.

Why is synchronization required?

The server must receive and verify the encrypted instruction before it can write a settled or rejected record to its demo ledger.

When is a payment actually settled?

Only when a backend transaction appears with status “Settled.” A local queue, mesh packet, or successful upload is not proof of settlement.

Why did synchronization fail?

Check the network connection and try again. Packets require the server public key that was cached during an earlier online visit. If the server restarted, older encrypted packets may no longer be decryptable.

Need a quick answer?

Queued does not mean paid. The demo cannot connect to UPI or move real funds.
